# Security Policy

## Supported versions

VioletVector AI is currently a `0.1.x` public preview. Security fixes are made
only against the latest commit on `main`; there is no production support or
security-service warranty.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private
vulnerability reporting page:

<https://github.com/marvalous123/violetvector-ai/security/advisories/new>

Include a concise description, affected commit, expected security boundary and
minimal reproduction using synthetic data. Do not include credentials, private
targets, client data, live exploitation, malware or unrelated reconnaissance.

You should receive an acknowledgement within seven days. Please allow time for
validation and a coordinated fix before public disclosure.

## Scope

In scope are defects that bypass exact target/scope validation, fresh approval,
execution bounds, emergency stop, audit integrity, evidence isolation, session
protection or report claim validation.

Out of scope are attacks against systems you do not own, social engineering,
denial of service, credential testing, third-party service testing and reports
that require exposing private evidence.
