# VioletVector AI Operational Value Gate

VioletVector AI is not an "AI SOC" and must not be marketed as one. Its value is the
deterministic, evidence-backed workflow around authorized security work. The
local model may explain or propose; it never substitutes prose for execution,
evidence, policy or analyst judgement.

## Release-candidate scope freeze

The first release candidate is a local, single-operator platform for authorized
labs and small engagements. It includes exact scope, deterministic policy,
expiring approvals, bounded capability execution, evidence, findings,
remediation, separately approved retest, Purple validation, QA-gated reports,
the synthetic guided demo, local advisory AI and the completed C2g one-shot
Windows observation.

The release candidate does not add continuous endpoint telemetry, autonomous
red/blue operation, production response, more execution adapters, cloud or
multi-user deployment, remote command, IPC/listeners or unrestricted scripts.
Those are separately reviewed future work, not hidden release blockers.

## Release outcomes

A professional release must demonstrate all of these on an authorized lab:

1. Import or define exact scope and reject an unapproved/private destination.
2. Turn a reviewed test step into bounded execution with an expiring approval.
3. Preserve command identity, output limits, hashes and evidence provenance.
4. Convert only supported evidence into a finding.
5. Assign remediation, attach fix evidence and run a separately approved retest.
6. Show the original/retest difference and generate a QA-gated report.
7. Stop active work and leave a recoverable, auditable terminal state.

The product is not ready for a business claim if any step requires hidden shell
work, fabricated demo state or an LLM assertion that cannot be replayed.

## Measurable proof

Every evaluated workflow records:

- operator steps and elapsed time;
- policy denials and approval latency;
- executed versus blocked versus skipped tests;
- evidence and finding counts, with unsupported claims rejected;
- remediation and retest completion;
- recovery result after interruption;
- model suggestions accepted, edited or rejected.

The benchmark is reduced analyst effort without reduced control. Model output
alone, alert summarisation and dashboard polish do not count as operational
value.

## Intended users

- learners use guided safe workflows and see why policy blocked an action;
- solo consultants use evidence, remediation, retest and reporting continuity;
- internal security teams use repeatable authorized checks and Purple evidence;
- senior operators use reviewed capability packs and can ignore the AI layer.

Every edition keeps the same scope, approval, audit and execution safeguards.
Advanced editions add workflow depth and integrations, not fewer guardrails.

## Release-candidate exit evidence

Only these items may block the frozen release candidate:

1. One retained, timed scope-to-report benchmark joining the authorized test,
   telemetry or tool evidence, detection/finding, remediation, approved retest
   and before/after result.
2. One clean-machine operator walkthrough proving setup, unlock, guided demo,
   evidence review, report export, backup and recovery instructions.
3. A clean full verification run and a single review of unresolved security
   findings; only reproduced release blockers are fixed.
4. A claim review that labels synthetic, source-verified and genuinely observed
   results separately and excludes production-protection claims.
